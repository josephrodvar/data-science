How it works

A recorder ran the real poller without publishing. Every poll cycle (about 60 s) it saved the raw source responses and the updates the poller computed from them. One frame is one cycle. For each vehicle the replay compares two predictions: the source tracker's (Hudson Link: CoachUSA, buswhere: Columbia County), which we pass through, and gtfs.zone's, computed by the delay-estimator from the GPS position alone. actual is when the bus really got to each stop, taken from later frames of the recording. Slider, arrow keys (shift = 10 frames) and space to play.

Stop table (click a vehicle)

seq / stop
The stops of the GTFS trip the vehicle was matched to. Highlighted row = source's next stop. Grey rows = already passed according to gtfs.zone.
sched
The GTFS scheduled time at the stop (511NY for Hudson Link, the Columbia County feed for buswhere).
source raw
What the source tracker said about this stop in this frame. Hudson Link: est = CoachUSA's estimated time, act = actual time (not seen so far), listed = stop listed with no time. Buswhere: eta Ns = seconds from the bus's last update, and the clock time that gives. Empty = source no longer lists the stop (Hudson Link lists only remaining stops).
source
The source prediction as we publish it in the GTFS-RT trip update, translated from source raw. It should equal source raw; a red cell means the translation changed it.
source delay
source minus sched. + is late, - is early.
gtfs.zone
sched plus gtfs.zone's delay, for stops not yet passed.
actual
Arrival at the stop (origin: departure), from the vehicle's GPS fixes over the whole recording, so it can lie in the future of the current frame (italic). With fixes within 100 m of the stop it is the first of them, and the tooltip has the last one (departure, so dwell shows). Otherwise ~ marks the interpolated time the GPS projection passed the stop. 60 s polling makes it good to about 30 s.
(error)
Small number after source / gtfs.zone: prediction minus actual. + = predicted too late.
error line
Mean absolute error of each prediction against actual, over this frame's remaining stops that have an actual.

Vehicle table and chart

next (source/gtfs.zone)
Next stop sequence according to the source (as we publish it) / according to the GPS position.
source delay
Our published delay at the next stop. We pass the source's prediction through, so this is the source's delay. Orange line in the chart.
gtfs.zone delay
The delay gtfs.zone's delay-estimator computes from the GPS position alone: it projects the position onto the trip's stops and compares the time with the schedule. Blue line in the chart. Independent of the source, so it is the cross-check.
chart
Delay over the trip. Shaded bands are flags. Click to jump to that time.

Flags (per trip and vehicle)

jump
Source delay moved 5 min or more between two frames.
behind
Source's next stop is behind gtfs.zone's (where the GPS says the bus is) for 2 min or more (the bus passed a stop the source still lists; the missed-stop problem).
diverge
Source and gtfs.zone delay differ by 5 min or more.
shared
One trip published for two vehicles at once.
unresolved
The source has a vehicle we published nothing for.

Map

lines
GTFS shapes of every trip seen that day, one color per route (feed colors when they differ, else derived from the route id). Selected trip drawn bold.
vehicles
Published vehicles in their route color, black outline = selected. Arrows point along the source's reported bearing (Hudson Link); buswhere reports none, so dots. Grey dashed = unresolved source vehicle.
stops
Selected trip's stops. Big orange / blue stop = next stop by source / gtfs.zone.
